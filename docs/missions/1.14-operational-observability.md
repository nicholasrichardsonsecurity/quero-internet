# Missão 1.14 — Observabilidade operacional

## Objetivo

Criar uma linha de visão operacional mínima para diagnosticar requisições sem registrar credenciais, corpo de requisições ou dados pessoais.

## Entrega

- `x-request-id` gerado ou validado em toda requisição;
- `x-correlation-id` propagado para correlação;
- log JSON por requisição com método, caminho, status, duração e identificadores;
- métricas básicas em `GET /metrics`;
- health/readiness existentes mantidos;
- métricas em memória, sem promessa de retenção ou alta disponibilidade;
- sem log de Authorization, cookies, body ou dados sensíveis.

## Operação

O operador deve usar o `x-request-id` para localizar a requisição nos logs. O `x-correlation-id` deve acompanhar uma jornada que atravesse API, worker ou adapter.

A versão inicial não substitui Prometheus, OpenTelemetry, armazenamento centralizado ou alertas persistentes. Esses componentes entram antes do piloto público conforme o ambiente de hospedagem e o SLO aprovado.

## Critérios de saída

- logs sanitizados e estruturados;
- métricas de volume, falhas, classes HTTP e duração média;
- endpoint de métricas sem dados de negócio;
- documentação dos limites da coleta;
- CI e Security Gate verdes.
