# Missão 1.9 — Agregações reais do dashboard

## Objetivo

Substituir a dependência exclusiva de dados de referência do dashboard por um endpoint backend de agregações reais, calculadas a partir do banco e limitadas por sessão, organização, tenants e RBAC.

## Entregas

- Novo módulo backend `DashboardModule`.
- Endpoint `GET /dashboard/operational`.
- Permissão dedicada `dashboard:read`.
- Política de escopo por persona em `dashboard-scope.ts`.
- Agregações por município, provedor, auditoria, suporte e operador de plataforma.
- BFF web `GET /api/dashboard/operational` para preservar cookie HttpOnly e não expor token ao navegador.
- Testes unitários de escopo e matriz RBAC.

## Regras permanentes preservadas

- Nenhum CPF/documento bruto é retornado.
- Nenhuma porta, CTO, splitter, topologia ou capacidade interna sensível do provedor é retornada ao município.
- Provedor vê apenas sua própria fila.
- Município recebe visão minimizada da operação.
- Auditoria recebe contagens e rastreabilidade agregada, sem ampliar dado pessoal.
- Suporte atua com mínimo privilégio.
- IA não decide elegibilidade, ativação, suspensão, encerramento ou autorização.

## Contrato inicial

```http
GET /dashboard/operational
Authorization: Bearer <token>
```

Resposta:

```json
{
  "persona": "municipal",
  "title": "Operação municipal",
  "subtitle": "...",
  "scopeLabel": "...",
  "dataSource": "database",
  "generatedAt": "2026-09-01T00:00:00.000Z",
  "kpis": [],
  "stages": [],
  "queues": [],
  "nextActions": [],
  "privacyNote": "..."
}
```

## Critérios de aceite

- `dashboard:read` deve estar disponível para papéis operacionais ativos.
- Endpoint deve resolver sessão pelo token e usar o contexto organizacional ativo.
- Contagens devem respeitar `tenantIds` da sessão.
- Escopo municipal deve filtrar `municipalityOrganizationId`.
- Escopo provedor deve filtrar `providerOrganizationId`.
- Auditoria/suporte recebem visão minimizada.
- CI e Security Gate precisam passar antes de merge.

## Próximo passo

Após esta missão, a próxima evolução natural é a **Missão 1.10 — conectar o dashboard web ao endpoint real com estados de loading, erro, fallback e atualização controlada** caso a UI ainda precise refinamento visual/UX.
