# Missão 1.10 — UX de Dados Reais no Dashboard

## Objetivo

Conectar o dashboard web operacional ao endpoint real `GET /api/dashboard/operational`, mantendo o token protegido em cookie HttpOnly e exibindo claramente quando os dados vêm do banco.

## Contexto

A Missão 1.8 criou a experiência visual do dashboard por persona. A Missão 1.9 criou agregações reais no backend. Esta missão fecha o ciclo de interface: a tela deixa de depender apenas de dados de referência e passa a consumir os agregados reais via BFF.

## Entregas

- A página principal carrega a sessão em `/api/auth/me`.
- A página consulta `/api/dashboard/operational` após validar a sessão.
- O dashboard exibe selo `DADOS DO BANCO` quando a resposta real é carregada.
- O dashboard exibe data/hora de geração enviada pelo backend.
- O token continua protegido pela rota BFF, sem exposição no navegador.
- Há estado de carregamento durante validação de sessão e agregação.
- Há fallback controlado para dados de referência quando o endpoint falha.
- Há alerta visível quando o fallback é usado.
- Há botão para recarregar dados.
- A barra de progresso da esteira agora usa o maior valor retornado pela agregação atual, não um número fixo.

## Limites preservados

- Sem CPF bruto.
- Sem documento hash ou identificador sensível.
- Sem topologia ou portas internas do provedor para município.
- Sem decisão automática por IA.
- Sem substituir autorização do backend por regra visual.
- Sem persistir dados do dashboard no navegador.

## Critérios de aceite

- CI verde.
- Security Gate verde.
- Build web verde.
- Dashboard renderiza com dados reais quando o endpoint responde.
- Dashboard mostra fallback e erro controlado quando a agregação falha.
- Sessão inválida redireciona para login.

## Fora do escopo

- Paginação de filas detalhadas.
- Gráficos históricos.
- WebSocket ou atualização em tempo real.
- OpenAPI completo.
- Seed governamental completo.
- Observabilidade avançada.
