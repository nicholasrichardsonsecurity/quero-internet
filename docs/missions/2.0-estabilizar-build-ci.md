# Missão 2.0 — Estabilizar build e CI

## Objetivo

Deixar `main` reproduzível antes de qualquer missão nova (regra de AGENTS.md: CI vermelho bloqueia missões).

## Entrega

- `pnpm-lock.yaml` versionado; CI, E2E, Security Gate e Vercel instalam com `--frozen-lockfile`.
- Dockerfile do worker instala só o subgrafo do worker (`--filter @quero-internet/worker...`), compatível com o lockfile do monorepo.
- `AuthLoginThrottle` declarado em `schema.prisma` (antes existia só nas migrations).
- Migration `20261025000000_schema_drift_alignment`: remove defaults de banco que o schema não declara e renomeia índices truncados pelo PostgreSQL para o nome esperado pelo Prisma.
- Novo passo de CI `prisma migrate diff --exit-code` contra o banco migrado: qualquer drift futuro quebra o build.
- ESLint 9 (flat config) na raiz e `pnpm lint` no CI.
- `asaas.client.spec.ts` corrigido: a chave deve ir no header `access_token` e nunca na URL, no corpo ou no retorno (o teste antigo exigia o impossível).

## Verificação local

`pnpm install --frozen-lockfile`, `pnpm db:validate`, `pnpm db:migrate:deploy` (PostgreSQL 16), `prisma migrate diff --exit-code`, `pnpm lint`, `pnpm typecheck`, `pnpm --filter @quero-internet/api test` (83/83), `pnpm build`.
