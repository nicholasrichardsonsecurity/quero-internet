# Auditoria de Segurança — 2026-08-25

Escopo: autenticação, BFF Next.js, sessão, RBAC, multi-tenant, dependências, Prisma e pipeline.

## Agentes de revisão aplicados
- Security Review Agent
- Code Review Agent
- Test Agent
- Database / Prisma Agent
- Telecom / GovTech Domain Agent

Os agentes são perfis de revisão especializados. Monitoramento contínuo determinístico é executado pela CI; não existe processo LLM autônomo em background no repositório.

## Gate automatizado instalado
- `pnpm audit` bloqueando High/Critical de produção.
- Semgrep para padrões OWASP e segredos.
- Dependabot semanal para npm e GitHub Actions.
- CI existente mantém migrations em PostgreSQL real, typecheck, testes e build.

## Achados

### HIGH — dependências PostCSS
O primeiro `pnpm audit` encontrou duas vulnerabilidades High em PostCSS transitivo do Next.js (leitura arbitrária/path traversal por source maps). Mitigação aplicada: override para `postcss 8.5.18` ou superior compatível.

Status: CORRIGIDO / aguardando novo gate.

### HIGH — deepmerge-ts transitivo do Prisma CLI
Vulnerabilidade de stack exhaustion em `deepmerge-ts < 8`, presente no caminho de tooling `prisma -> @prisma/config`. Não pertence ao runtime de produção, mas permanece relevante para build/migration.

Status: PENDENTE CONTROLADO. Atualizar Prisma somente após teste de migration/build; não forçar major sem validação.

### MEDIUM — mensagens upstream no BFF
O BFF podia repassar mensagem textual de erro 5xx retornada pela API. Isso pode revelar detalhes internos caso algum handler futuro exponha erro sensível.

Status: CORRIGIDO. Erros 5xx agora são normalizados.

### MEDIUM — validação de entrada do login BFF
JSON inválido, payload anômalo e resposta inválida do upstream não tinham tratamento explícito.

Status: CORRIGIDO. Limites básicos, 400/502/503 e validação da resposta foram adicionados.

### MEDIUM — lockout de conta por identificador
O rate limit atual usa hash do e-mail como único sujeito e bloqueia após cinco falhas. Um atacante que conheça o e-mail pode provocar bloqueio temporário da conta.

Status: PENDENTE. Próximo hardening deve combinar sujeito + origem confiável (IP no BFF/proxy) e política progressiva sem permitir bypass por header do cliente.

### MEDIUM — imutabilidade da trilha de auditoria
`AuditLog` é tratado como append-only pela aplicação, mas o schema/banco ainda não impede UPDATE/DELETE por uma credencial de aplicação comprometida.

Status: PENDENTE. Implementar proteção no banco/role dedicada antes de produção.

### LOW/MEDIUM — integridade do contexto de sessão
`Session.activeOrganizationContextId` é UUID sem FK explícita para `Organization`. A autorização falha fechado se o valor for inválido, porém falta integridade referencial no banco.

Status: PENDENTE DE MODELAGEM.

### OPERACIONAL — validação de sessão em toda navegação
O middleware consulta `/auth/me` para cada request protegido. É seguro por falhar fechado, mas aumenta latência e pode amplificar carga na API.

Status: ACEITO NO MVP. Avaliar cache curto/server session envelope sem relaxar revogação.

## Observações do pipeline
`actions/dependency-review-action` não funciona no repositório privado sem Dependency Graph + GitHub Advanced Security. Foi removido do gate obrigatório para evitar falso vermelho; o controle foi substituído por audit de produção + Semgrep + Dependabot.

## Critério de saída
Nenhum achado Critical/High de runtime pode permanecer aberto para merge de release. Achados Medium precisam de mitigação, aceite explícito ou missão de correção antes de produção.
